# 百人一首テキストエディタ

ふつうのテキストエディタの裏で、いま書いている文を小さな判定モデルが読み、連想される百人一首の札を
画面の端に静かに差し出す。

https://qurihara.github.io/hyakunin-isshu-editor/

書いた文章は、どこへも送らない。判定は、利用者の端末のブラウザの中だけで行う。

## しくみ

書いている文を、12個の主題（待つ、逢えない、人目、別れ、約束、涙、独り、月、秋、春、冬、時）について
「有」か「無」かで判定し、その配列に近い札を100首から選ぶ。100首の側の主題は、あらかじめ人手で付けてある。

判定は、TypeSafe社の jev（System One型モデル）の考え方を借りている。文章を書かせるのではなく、
型の決まった問いを並べて、確率つきの答えを一度に返させる方式である。その再現実装である kev を手がかりに、
ここでは12個の問いを1本の系列にまとめ、次の形で一度に読み取る。

```
文章：窓の外に月が出ていた。眠れないまま、しばらく眺めていた。
待つ？ 逢えない？ 人目？ 別れ？ 約束？ 涙？ 独り？ 月？ 秋？ 春？ 冬？ 時？
```

各「？」の次の位置に来る語（有か無）を12か所まとめて読む。12回ぶんの計算が1回で済み、
判定はMacのブラウザで0.13秒から0.3秒で終わる。

## 作っているもの

| 部品 | 中身 |
|---|---|
| 土台のモデル | [llm-jp/llm-jp-3-150m](https://huggingface.co/llm-jp/llm-jp-3-150m)（1億5千万パラメータ、Apache-2.0） |
| 追加の学習 | LoRA。日本語の文章1602件に12主題の正解を付けて学習した。うち300件は主題を直接指す語を使わず情景へ託して書いた文、300件は語句を共有したまま意味を反転させた対、202件は行為と情景の描写だけで主題を表す文である。取り分けた235件での正答率は0.955 |
| 実行 | 学習した差分を土台に統合し、ONNXへ書き出して4ビットに量子化した。ブラウザでは [transformers.js](https://github.com/huggingface/transformers.js) が WebGPU で動かす |
| 判定器の大きさ | 152MB。GitHubの1ファイル100MBの制限に合わせ、40MBずつに分けて置いてある（`model4/onnx/parts/`）。ブラウザ側でつなぎ、保存領域へ入れてから読み込む |
| 札の絵 | Wikimedia Commons のパブリックドメインの絵札100枚 |

## 手元で動かす

```bash
python3 -m http.server 8775
```

http://localhost:8775/ を開く。

## ライセンスと出典

- 土台のモデル llm-jp/llm-jp-3-150m は Apache-2.0。
- 絵札は Wikimedia Commons の [Ogura Hyakunin Isshu (complete set)](https://commons.wikimedia.org/wiki/Category:Ogura_Hyakunin_Isshu_(complete_set)) から取得した。いずれもパブリックドメインである。出典の一覧は `images/credits.json` にある。
- 歌の背景と主題の判断には、[小倉山荘の解説](https://ogurasansou.jp.net/columns_category/hyakunin/) を参考にした。
